# Codebase Report for Antigravity Extension

## 1. Executive Summary

**Antigravity** is a pyRevit extension designed for architectural visibility management. It utilizes a **Factory Pattern** (`factory_setup_v4.py`) to dynamically generate its UI structure (buttons, stacks, pulldowns) based on configuration data.

**Current Status:**
*   **Structure:** Well-defined directory structure compliant with pyRevit standards (`.tab` > `.panel` > `.stack/.pulldown` > `.pushbutton`).
*   **Logic:** The core logic files (`vis_manager.py`, `preset_manager.py`) are currently **stubs/placeholders**. They contain function signatures but lack implementation logic (e.g., interaction with the Revit API).
*   **Testing:** A robust test suite (`test_suite.py`) exists and uses extensive mocking to simulate the Revit environment, confirming the intended architecture even though the implementation is pending.

## 2. Directory Structure

The project follows a standard pyRevit extension layout, generated by a build script.

```text
.
├── Antigravity.tab/                # Generated Extension UI Root
│   └── Arch_Toggles.panel/         # Main Panel
│       ├── 01_Master.stack/        # Stack: Snapshots, Search, Reset
│       ├── 02_Model.pulldown/      # Pulldown: Model Category Toggles
│       ├── 03_Annotation.pulldown/ # Pulldown: Annotation Category Toggles
│       └── 04_LinkTools.stack/     # Stack: Link Management & Presets
├── lib/                            # Core Library (Runtime Logic)
│   ├── constants.py                # Configuration (Category lists)
│   ├── vis_manager.py              # Visibility Logic (Stubbed)
│   └── preset_manager.py           # Preset Logic (Stubbed)
├── factory_setup_v4.py             # Build Script (Generates UI)
├── test_suite.py                   # Unit Tests (Mocks Revit API)
├── README.md                       # Project Documentation
└── TOOLS_LIST.md                   # Tabular List of Tools
```

## 3. File Analysis

### A. Core Scripts

#### `factory_setup_v4.py`
*   **Purpose:** The "Builder" script. It deletes the existing panel and regenerates it from scratch.
*   **Key Features:**
    *   **Dynamic SVG Generation:** Creates unique icons for every tool using `System.Drawing` logic (ported to Python text manipulation here).
    *   **Lazy Loading:** Generates `script.py` files that import from `vis_manager` only when clicked, improving startup time.
    *   **Configuration:** Reads `MASTER_CATEGORY_LIST` and `ANNOTATION_CATEGORY_LIST` from `constants.py` to create buttons.

#### `lib/vis_manager.py`
*   **Purpose:** The runtime engine for visibility changes.
*   **Current State:** **STUB**.
    *   `toggle_category(cat_name)`: Defined but empty (`pass`).
    *   `set_all_visibility(visible)`: Defined but empty (`pass`).
*   **Intended Behavior:** Should interface with `Autodesk.Revit.DB` to hide/unhide categories in the active view.

#### `lib/preset_manager.py`
*   **Purpose:** Handles saving/loading named visibility presets.
*   **Current State:** **STUB**.
    *   `apply_preset(name)`: Defined but empty (`pass`).

#### `lib/constants.py`
*   **Purpose:** Single source of truth for category lists.
*   **Content:**
    *   `MASTER_CATEGORY_LIST`: ['Walls', 'Doors', 'Windows', 'Furniture', 'Floors', 'Roofs', 'Ceilings', 'Columns', 'Structural Columns', 'Stairs']
    *   `ANNOTATION_CATEGORY_LIST`: ['Dimensions', 'Grids', 'Levels', 'Tags', 'Text Notes']

#### `test_suite.py`
*   **Purpose:** automated testing.
*   **Technique:** Uses `unittest.mock` to simulate the entire Revit API (`Autodesk.Revit.DB`, `pyrevit.revit`, `doc`, `view`), allowing tests to run outside of Revit.
*   **Coverage:** Tests structure implies validation for toggling logic, hiding all categories, and link warnings.

### B. Generated UI Components

The `Antigravity.tab` folder contains the actual tools users see in Revit.

| Group | Component | Content |
| :--- | :--- | :--- |
| **01_Master** | **Snapshots** (Pulldown) | Save, Load, Delete |
| | **Search** (Button) | Search & Toggle Categories |
| | **ResetAll** (Button) | Unhide All Architecture |
| **02_Model** | **Model Categories** (Pulldown) | Individual toggle buttons for all categories in `MASTER_CATEGORY_LIST`. |
| **03_Annotation** | **Annotation** (Pulldown) | Master Hide/Unhide + individual toggles for `ANNOTATION_CATEGORY_LIST`. |
| **04_LinkTools** | **Links** (Pulldown) | HideLinks, UnhideLinks, FixLinks |
| | **Isolate** (Button) | Isolate Selected Category |
| | **Presets** (Pulldown) | Generated buttons for presets (e.g., from `presets.json` if it existed). |

## 4. Key Observations

1.  **Skeleton Implementation:** The project has a highly sophisticated "shell" (build system, UI generation, test mocks) but the actual engine (`vis_manager.py`) is currently empty.
2.  **Deterministic Icons:** The build script generates SVG icons with initials and random (but seeded) colors, ensuring a consistent but colorful UI without needing external image assets.
3.  **Extensibility:** Adding a category to `constants.py` and running `factory_setup_v4.py` immediately updates the UI with new buttons and icons.
